## Elevator pitch

> Spot prices are what every app shows, but they're less than half of the bill. wattslot adds the grid company's time-of-use tariff, the transmission tariffs, electricity tax and VAT for every 15-minute slot, so "cheapest time to run the dishwasher" is answered with the price you actually pay.

## What it is

A public website and API, live at [wattslot.mateokadiu.com](https://wattslot.mateokadiu.com):

1. **Ingestion.** One cron Worker pulls day-ahead prices, CO₂ forecasts and DataHub tariffs from Energi Data Service. A schedule function decides what's due on each 5-minute tick: day-ahead every 5 minutes around publication (12:50–14:30), CO₂ every half hour, tariffs nightly. Rate limits are respected via the API's `Retry-After`.
2. **Pricing.** A pure `pricing` package turns spot price + tariffs into an all-in price per quarter hour. Tariffs are published per *local* hour with local wall-clock validity, so DST days come out as 92 or 100 slots, not 96.
3. **API + website.** `GET /v1/prices`, `/v1/co2` and reference data, with an OpenAPI document. The website is a Next.js static export served by the same Worker: a verdict ("good time to use power" or "wait until 14:00, 23% cheaper"), a task planner and a stacked chart showing what you pay for. English, Danish, German, Norwegian and Swedish.
4. **Plans and notifications.** Say what to run and by when, and wattslot offers the cheapest, a balanced and the greenest plan, compared with starting now and with a midnight timer. A saved plan, with no account (a random token kept in the browser), runs as its own Cloudflare Workflow: it sleeps until each start and stop and sends a Web Push notification, and you can add it to your calendar.
5. **Power outages.** Current outages and planned work from every Danish grid company, refreshed every 5 minutes, with each company's fault line.

## The problem I was solving

Since October 2025, the day-ahead market settles in 15-minute slots, and grid companies charge time-of-use tariffs: in winter, the 17:00–21:00 peak tariff is about nine times the night rate. Planning on the spot price alone picks the wrong slots more often than you'd think. Over 393 days of Copenhagen data, a spot-only plan for an overnight EV charge chose different quarter hours than the full-price plan on **73%** of days.

Smart charging pays: on a year of real prices and tariffs, charging an EV in the cheapest quarter hours instead of on plug-in cuts its electricity cost by about **48%**.

Getting the full price right means handling the messy part: hundreds of tariff series, each with 24 local-hour prices, periods that start and end on local wall-clock times, and one grid company that reuses the same charge code for a subscription and a tariff.

## Key decisions

1. **The free plan as a design constraint.** Workers get 10 ms of CPU per request, so the website is a static export instead of server-rendered React, and bulk writes go through a single `json_each(?)` statement instead of a query builder (~7 ms → ~0.8 ms).
2. **Strict tariffs, honest fallback.** Overlapping tariff periods never happen in valid data, so they throw instead of silently picking one. When a grid company's tariff can't be priced, the API falls back to the spot price and says so in a `note`, rather than showing a wrong total.
3. **Money as integer micro-units.** VAT is rounded half away from zero, once. Property tests (fast-check) check the breakdown always sums to the total, prices are monotonic in the spot price, and DST days tile correctly across 40 years.
4. **Edge cache with self-enforced freshness.** Responses are cached by completeness: a minute while tomorrow's prices are pending, a day for the past. The Worker stores the cache time itself, because the zone's browser-cache setting would otherwise override it.
5. **Real stack in end-to-end tests.** Playwright seeds a local D1 by running the real cron against recorded API fixtures, then drives the built site under `wrangler dev`, with an axe audit on every run.
6. **A workflow per plan that replays exactly.** A Workflow re-runs its code after every sleep, so each plan's actions come from the stored plan alone, never the clock, and step names are fixed per plan version. A retried step can't notify twice, and pushes stay under the free plan's 50 requests per workflow.
7. **Web Push without a library.** Message encryption (RFC 8291) and VAPID signing (RFC 8292) are written on Web Crypto and checked against the RFC's test vector in Node and in `workerd`. One push takes about 0.4 ms of CPU. Device subscriptions are stored with envelope encryption, and the Worker only sends to the browsers' own push services.
